Key Product Insights

  • OAUTH2 is the dominant auth method (65 apps), reflecting the industry's shift toward delegated authorization — especially in CRM and Productivity categories where integrations act on behalf of end-users.
  • 81 of 100 apps (81%) offer self-serve developer access. The remaining 19 gated apps are concentrated in enterprise-facing categories (Finance, Ads, Commerce) where compliance, partner programs, and revenue protection justify friction.
  • Finance APIs overwhelmingly mandate OAuth2 and API keys due to regulatory compliance requirements — Stripe, Plaid, Brex, and Xero all enforce token-based authentication with strict scoping.
  • AI-native startups overwhelmingly provide simple API keys, optimizing for developer speed and quick prototyping over enterprise security controls.
  • Marketing and Ads APIs have the highest approval friction — Google Ads, LinkedIn Ads, and Meta Ads all require manual developer review, app approval processes, or developer token requests before API access is granted.
  • Easy wins are concentrated in Data, SEO and Scraping, Support and Helpdesk, Developer, Infra and Data platforms, Finance and Fintech, Productivity and Project Management because these categories expose stable REST APIs, standard OAuth2 flows, and self-service developer portals with generous free tiers.
  • 10 apps are currently blocked from agent toolkit integration. The most common root cause is enterprise/partner gating — not technical limitation — meaning these could be unlocked through business development outreach.

4. Common Blockers (Grouped)

The following recurring patterns prevent immediate buildability:

  • Paid subscription required (4 apps) — e.g., Ecwid: API access requires a paid Ecwid store plan.; Squarespace: Requires a paid Squarespace Commerce subscription to access API.; Aircall: Requires a paid Aircall subscription (Essentials or Professional) to access the API.
  • Manual approval / Developer review (3 apps) — e.g., LinkedIn Ads: API access requires applying to the LinkedIn developer program and waiting for approval.; Google Ads: Requires admin approval for developer token.; Meta Ads: App Review required for full API access and production usage.
  • Enterprise contracts / Contact sales (3 apps) — e.g., Salesforce Commerce Cloud: No free developer sandbox. Requires existing partner or customer contract for on-demand sandboxes.; DealCloud: No self-serve access, free tier, or sandbox available without an enterprise contract and partner contact.; PitchBook: API access requires enterprise contract and account manager contact.

6. Agent Pipeline Architecture

This report was generated by an autonomous multi-agent pipeline. Each agent has a defined role and strict instructions.

graph TD A["📋 Input: App List (JSON)"] --> B["🔧 Lead Researcher (Orchestrator)"] B --> C["👷 Research Workers (×5 parallel)"] C --> D["🌐 Web Search & Doc Crawling"] D --> E["📝 Extract Auth / Access / API / MCP"] E --> F["💾 Save to data/raw/*.json (Pass 1)"] F --> G["🔍 Verifier Agent (Stratified Sample)"] G --> H["✅ Cross-check Evidence URLs"] H --> I["📊 Aggregate Patterns (aggregate.py)"] I --> J["📄 Generate Report (generate_report.js)"] J --> K["🎯 output/report.html"]

Where a Human Was Needed

  • Hallucinated GitHub repos: The agent occasionally invented MCP server URLs that returned 404 (e.g., Discord, Jira, Shopify). The verifier caught and corrected these.
  • Misclassified access gates: Freemium models (Zoho Cliq, Airtable, Firecrawl) were sometimes classified as "none" or "gated" incorrectly.
  • Enterprise approval flows: Apps like LinkedIn Ads, Amazon SP-API, Google Ads, and Salesforce Commerce have multi-step approval processes that the agent could identify but not navigate.
  • Orchestration design: Humans defined the app list, JSON schema, batch sizes, and verification sampling strategy.
